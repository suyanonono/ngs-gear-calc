# OP最適化

- 通常ボタンは選択中のプリセット・レベル・クリティカル条件を使う。アバンダク選択時には専用ボタンへ案内する。プリセット未選択なら確認後に能力なしで実行できる。
- アバンダク用ボタンはアバンダク選択時のみ実行する。現在のレベルと、通常OP・入力済みEXの異なる能力名の数（上限20）による倍率を探索で評価する。
- 両ボタンとも武器通常OP5枠＋防具24枠を対象とする。EX3枠は未入力でも予約し、入力済みEXを変更しない。
- 未入力EXは各枠で異なるEXを装着する想定として種類数に加算する。未入力EXのステータス・条件倍率は仮定せず、実行後の注意表示に未入力数と再最適化の案内を残す。画面の期待値指数には仮想EXを加算しない。
- 通常OPの同系統排他、ユーゼ・ユディの各1個制限を維持する。異能力数は正規化前の能力名で数えるため、別部位の通常版・S版等の使い分けも評価する。
- 貪欲法と交換改善で探索する。全29枠が有効な現在構成からも交換改善を行い、同じ評価条件で良い方を採用する。大域最適解の保証はない。手入力の独自能力・未充足枠・無効構成は比較用の開始構成にはしない。
- スロット比較側の既知の計算不整合は今回の対象外。

検証: scripts/test_optimizer.cjs を Node.js で実行。ブラウザDOMの代替を使い実データで枠数、排他、EX保持、アバンダク評価、確認・キャンセルを確認する。
